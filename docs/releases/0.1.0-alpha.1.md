# GhostTrace 0.1.0-alpha.1 (prerelease notes)

Not released yet. This file is the note set that `xtask package` ships inside an
early archive; the publication itself follows Section 20 of the master plan.

## What this build is

An alpha command-line workbench for local-first folder capture and review:

- create a case directory, capture one or more source roots read-only, and
  record a SHA-256 for every stored object;
- record per-path coverage (`captured`, `excluded`, `inaccessible`, `unstable`,
  `vanished`, `unsupported`, `unobserved`) instead of silently skipping;
- query the application-clock timeline with bounded filters;
- diff two captures of the same roots with coverage-aware classes — absence is
  never reported as deletion, equal hashes are move *candidates*, and a
  coverage gap makes the answer `unknown`;
- verify a stored manifest and its objects by independent re-hashing;
- export a versioned JSON report plus an inert, self-contained HTML report.

There is no desktop UI in this build and no network behavior of any kind.

## Verified platform

- Linux x86_64, Rust 1.99.1, glow/egui desktop stack (desktop not in this
  archive).
- Capture is verified on Unix only. Windows capture returns an explicit
  `Unsupported` stub; do not treat a Windows build as a capture baseline.
- Live screen-reader (Orca/AT-SPI) smoke was not completed on the build host;
  the accessibility gate remains open and is tracked in `docs/releases.md`.

## Install from an archive

```bash
sha256sum -c ghosttrace-0.1.0-alpha.1-<target>.tar.gz.sha256
tar -xzf ghosttrace-0.1.0-alpha.1-<target>.tar.gz
./ghosttrace-0.1.0-alpha.1-<target>/bin/ghosttrace --help
```

`build-info.json` inside the archive records the target triple, rustc version,
git commit, and a SHA-256 for each packaged file. Compare it to the values in
the release announcement before trusting a build.

## Known limitations

- Reports and manifests are **unsigned**. They prove byte integrity, not
  authorship or chain of custody.
- An acquisition cancelled by SIGINT writes no manifest; it is recorded as
  cancelled/partial and cannot be verified as a complete capture.
- Coverage gap lists in reports are bounded; the complete ledger lives in the
  case database.
- Diff proves only what the two captures recorded. It never establishes
  deletion, copying, or intent.
- No URL in any artifact is fetched, and no evidence bytes leave the machine.
